# 解法設計約束（修任何東西前先讀）

> 來源：2026-08-04 紅軍複查。同一個病三次復發 —— 判準由被驗方書寫，
> 不由執行事實推導。三個實例記在 C2/C3/C4 底下。

## 鐵律

事實只能推導，不能複製。判準必須是被驗方編不出來的東西。

## 五條硬約束

### C1 — 判準來自執行事實，不來自宣告

禁止把「檔案存在」「字串有寫」「欄位有填」當通過條件。

合法判準只有三類：

- 執行期產物：log 行、exit code、mtime、rowid、DB 筆數
- 靜態關係：呼叫點、import 邊、reference count（排除自身與 cache）
- 差異：動作前後某個具體檔案的內容差

寫下判準前先答：**「如果這東西根本沒跑，哪個檔案的內容會不一樣？」**
答不出來 → 沒有判準 → 不准宣稱修好。

### C2 — 檢查必須無條件觸發

禁止「符合某書寫格式才檢查」。

檢查若有 `if` 前綴，必須證明：分母是多少、觸發了幾條。
覆蓋率 0 的檢查等於沒有檢查，視為未修。

> 實例：`brain/lint.py::check_consumers` 的呼叫者驗證只在 consumer 字串
> 含 `(` 時觸發，而 `brain/consumers.yaml` 裡沒有任何條目含括號 —— 修了等於沒修。
> 覆蓋率現跑：
> ```bash
> grep -c '^      - "' brain/consumers.yaml          # 分母
> grep '^      - "' brain/consumers.yaml | grep -c '('  # 分子
> ```

### C3 — 接線必須驗簽名，不只驗名字

換掉任何被呼叫的函式時：

1. 列出**所有**呼叫點（不是只改一個）
2. 對每個呼叫點做 `inspect.signature().bind(*args, **kwargs)`
3. 全數 bind 通過才算接上

> 實例：`laap/chatflow.py` 有多個 `llm_respond` 呼叫點，換函式時只改了其中一個；
> 且 `respond_nd` 沒有 `delta` 參數，呼叫點卻傳了 —— 每次呼叫必拋 TypeError。
> 驗法：`inspect.signature(fn).bind(...)` 逐一 bind，不是讀程式碼。

### C4 — 錯誤不准降級成靜音

- 禁止 `except Exception: logger.debug(...)`。型別／屬性／匯入錯誤一律 `warning` 以上。
- 禁止 `2>/dev/null` 罩住整段邏輯；只准罩已知且無害的單一噪音。
- 禁止空字串走進成功分支 —— fallback 條件要看內容，不看命令 exit code。

> 實例一：上面那個 TypeError 被 `logger.debug` 吞掉，靜默 fallback，外面看起來正常。
> 實例二：`scripts/aris-bootstrap-summary.sh` 的 handoff 檢查缺 `import os`，
> NameError 被 `2>/dev/null` 吞掉，空檔讓 `cat` 成功（exit 0），
> 於是空字串走進成功分支，渲染成 `🟢`（假綠）。

### C5 — 驗證換一條路

不准用「產生它的同一條路」驗它。

- 改程式 → 用 log／實跑驗
- 改設定 → 用實際行為驗
- 同路重跑三次不算三個證據，算一個

## 交付格式（少一項就是沒做完）

| 欄位 | 要求 |
|---|---|
| 根因 | 一句話 + `檔案:行號` |
| 判準 | 具體檔案／log 行／指令，且滿足 C1 |
| 覆蓋率 | 這次檢查掃了 N 條中的 M 條，M/N 要寫出來 |
| 實跑證據 | 貼原始輸出，不是描述 |
| 反證 | 「如果沒修好，這裡會看到 X」，並說明 X 沒出現 |
| 未修 | 這輪沒動到但已知的洞，逐條列 |

## 禁止的說法

- 「已修復」「全數修復」「已接上」—— 除非附 C1 判準的實跑輸出
- 「應該可以了」「理論上」
- 沒有量測來源的百分比與 token 數字

## 完成前自檢

1. 我的判準，被驗方能不能靠改寫文字就通過？能 → 判準無效
2. 這個檢查實際掃了幾條？0 條 → 未修
3. 錯誤發生時，我看得到嗎？看不到 → 未修
4. 我是用產生它的同一條路驗的嗎？是 → 未驗
