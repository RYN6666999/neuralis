### 對於測試本身的誠實判斷

> 這次的結論是關於「Aris 的學習能力」還是關於「我設計的 mock 分數」？

**關於後者，而非前者。** 理由：

1. Mock 的 score function 直接對選擇角度給分，這在真實環境中不存在。
   真實環境中 `_score_result` 是從 gbrain 檢索結果的品質決定的，
   不是從 prompt 的關鍵詞決定的。
2. RPE 信號乾淨得可疑：選「作法」永遠得 0.9，不選永遠得 0.1。自然界沒有這麼乾淨的訊號。
3. 真實環境中還有其他干擾：gbrain 檢索的隨機性、同一 query 在不同時間的結果差異、
   explore 同時影響 tool 和 angle，造成複合雜訊。

**學到的是「作法=高分」這個規律。這證明了 bandit 學習機制運作正常，
但不等於在真實條件下它會「學到東西」。「會學」不等於「學到對的」。
後者需要沙箱（外部考卷）。**

## 第四個洞：trust 飽和

**發現時間**：2026-07-26

**位置**：`laap/agency.py:101-102` + `laap/agency.py:216-218` + `laap/agency.py:222-223`

```python
self._trust_scores: dict = {"user": 0.3}   # entity → trust 0-1
self._trust_decay_rate = 0.0005             # 每次評估衰減量

# 每次評估時
for entity in self._trust_scores:
    self._trust_scores[entity] = max(0.0, self._trust_scores[entity] - self._trust_decay_rate)

# 每則使用者訊息（note_interaction）
old = self._trust_scores.get(entity, 0.0)
self._trust_scores[entity] = min(1.0, old + 0.03)

# 使用處（_evaluate）
trust = self._trust_scores.get("user", 0.0)
drives["relatedness"] = drives.get("relatedness", 0.0) * (1.0 + trust * 0.5)
```

**數學上的必然性**：
- 每次 `note_interaction`（每則訊息） +0.03
- 每次評估（每 60s） −0.0005
- 使用者每秒發言量大約每 60s 一次 → net ≈ +0.0295/cycle
- 從初始 0.3 到飽和 1.0 需要 ~24 次互動（約 24 分鐘密集對話）
- 一旦到 1.0，永遠停在 1.0 — 因為 decay 0.0005 被下一個 note_interaction 的 +0.03 壓過
- 要跌回 0.9 需要連續 200 秒（~3.3 分鐘）無互動，但 3.3 分鐘內通常又有新訊息

**影響**：
- `trust[user]` 永遠在 0.95–1.0 之間，是一個裝了刻度的常數
- `drives["relatedness"]` 的增益永遠是 1.5x，與使用者真實關係無關
- `_form_intent()` 中唯一代表「這個人可不可信」的訊號已死亡
- 這不是 bug，是**設計錯誤**：增益率和衰減率的比例不平，數學上保證飽和

**掛帳（這輪不修）**：
- 修它需要動決策邏輯（不是改個數字）
- 可能方向：非線性增益、交互式信任、或讓信任影響角度權重而非 drive 倍率
