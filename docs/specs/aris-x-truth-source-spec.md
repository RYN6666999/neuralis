## 1. 四層：L3 沒有捷徑
| 層 | 例 | 唯一可靠方法 | 成本 | 副作用 |
|---|---|---|---|---|
| L1 靜態 | 檔案、誰 import 誰、code 寫什麼 | 讀 code | 免費 | 無 |
| L2 慢變 | launchd、埠、進程、mtime、schema | 現場採樣 | 秒 | 無 |
| L3 行為 | 對話讀哪顆 PSI、記憶召不召回 | **踩一腳看它叫** | 貴 | 有 |

**禁止**：拿 L2 方法（mtime）解 L3 問題（誰讀）。mtime 只證明「誰寫」。

## 2. 行為探針（L3 唯一手法）
- 不問「讀哪個檔」（不可觀測）；問「**只有那條路通了才答得出的問題**」。
- **指紋必須不可猜**：hash / 亂數 / 當下時間戳。防 LLM 用常識蒙混。
- **單次不算數**：需跑 **N 次**看穩定性，成本 = 探針成本 × N。

| 要證明 | 探針 | 通過判準 |
|---|---|---|
| 對話讀 gbrain seed | 問 commit hash | 答出 `bedad23` |
| 對話讀 Rust PSI | 對話問 certainty，比對 rust-latest | 數值吻合 |
| 情緒影響回話 | 同問題高/低 arousal 各問 | 語氣有差（**只有 Ryan 能判**） |
| 記憶寫得回 | 告訴唯一字串，隔輪問回 | 答得出來 |

## 3. 輸入 = 架構圖（不是表）
```
節點 = 元件（進程/檔案/模組）
邊  = 三種：
  ━━━ 實線  行為探針證實通（L3，最強）
  ┄┄┄ 虛線  code 說有，未證實（L1 未驗）
  ╳╳╳ 紅叉  code 說有，探針證實沒通（矛盾）
```
**刪除清單自動從退化結構長出：**
| 圖上樣 | 意義 | 動作 |
|---|---|---|
| 節點無任何入邊 | 沒人用它 | 候選刪除（`laap_semantic_memory`） |
| 節點所有出邊皆紅叉 | 接了接不上 | 候選刪除（Rust daemon 現況） |
| 兩節點同職、各自有入邊 | 重複 | 候選合併（8 份 PSI） |

表只能列你想到的；圖會自己秀出孤島。

## 5. TTL（用保鮮期取代可重現）
> 「同 ground 同 View」做不到（PSI 2000Hz 一秒就變）。改成每事實帶保鮮期，過期自動灰。

| 事實 | TTL |
|---|---|
| PSI 數值 | 2s |
| 進程/埠 | 60s |
| launchd job | 5m |
| 檔案/code 結構 | 1h |
| **L3 探針結論** | **24h 或「相關檔案改動」即失效** |

最後一條：改 `memory_store.py` → 所有靠它的行為結論當場作廢（git diff 算，不猜）。

## 6. 五色（含 ❓ 測不到）
| 色 | 義 |
|---|---|
| 🟢 通 | 行為探針證實 |
| 🔴 不通 | 探針證實沒通 |
| 🟡 矛盾 | code 說 A 實測 B（可能是文件沒寫全） |
| ⚪ 未測 | 還沒跑 |
| ❓ 測不到 | 工具失敗 / 技術上量不到 |

**❓ 最重要**：`pgrep` 非 UTF-8 靜默回空曾把「查不到」報成「0 實例」。沒有這色，X 會把失敗呈現成「疆域是空的」。

## 8. 閘門 HTML＝簽核 UI（含打勾/取消）
- 每個可簽格是 **checkbox**：打勾=簽核過、取消=撤銷。
- **勾選狀態本地持久化**（localStorage），reload 不丟；總督判顯示「已簽 X / 待簽 Y」。
- 機械事實不顯示勾選（機器判）；只有上面第 7 節三種才給勾。
- TTL 過期的格子自動變灰、勾選自動失效（保鮮期勝過人工簽）。
