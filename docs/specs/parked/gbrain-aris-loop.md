# gbrain-aris-loop · 耦合公理 + 校準層

> 骨架定於 2026-07-20 對話，2026-07-24 落檔搶救（先前只在對話中，未進 docs/specs/）。
> **憲法級：優先於本 spec 一切後續設計。** GBrain × Aris 之間**每一個**接點，加接點前逐條檢查。
> 一句話：用得好是校準，用得不好是打架；分水嶺不在系統多強，在每個接點有沒有講清楚「衝突時聽誰的」。

## 0. 定位

GBrain（證據腦庫，冷）× Aris（neuralis 情緒/agency overlay，暖）要耦合。
最自然的接點是**校準函數**：證據強度 → 宣稱語氣強度。

- GBrain 出「事實有多可信」。
- Aris 出「用什麼態度說、要不要去補證」。
- 兩者在「校準」這一點上本該是同一顆心臟：GBrain 當剎車、Aris 當油門，**剎車有最終權**。

沿用甲（認知光錐保守路）精神：帳本層 zero-LLM 確定性程序，情緒碰不到該路徑。

## 1. 耦合公理（四條 · 加接點前逐條過）

### 公理零 · 每個接點都必須回答「衝突時聽誰的」

沒有明確最終否決權的接點 = 未來打架的火種。答不出這句的接點，不准上線。
（對映甲：「鑰匙永遠在 Ryan」＝明確最終否決權，非對等否決。）

### 公理一 · 帳本對態度有否決權，態度對帳本沒有

- **證據層（冷）** 裁判「事實是什麼」，有最終否決權。
- **情緒/agency 層（暖）** 裁判「用什麼態度說、要不要去補證」，無事實否決權。
- Aris 再想推進，帳本說證據不足 → 輸出必須維持保守。情緒可讓語氣暖、可驅動補證，
  **不能讓 🔴 變 🟢**。
- 防的死法：對等否決造成的僵局。**明確優先級才製造校準，對等否決製造僵局。**

### 公理二 · 情緒只能單向讀帳本，不能寫帳本

- affective 態可**讀**證據強度 → 決定語氣與探索。
- affective 態**絕不寫回**證據判定。物理性切斷「情緒→帳本」迴路。
- 實作：帳本層走 zero-LLM 確定性程序（沿用 neuralis overlay），情緒碰不到該程式碼路徑。
- 防的死法：情緒污染帳本 → 兩系統狼狽為奸、一起自我欺騙（比僵局更危險，因為看起來很順）。

### 公理三 · 校準訓練用延遲真實結果，不用當下採納感

- 校準函數（證據強度→宣稱強度）的獎勵信號 = 「判斷後來被證明對不對」，
  **不是**「Ryan 當下採納了」。
- 沿用甲 E1.2（recall 才有獎）+ E1.1（de-game 抗刷分）抗信號污染思路。
- 無延遲驗證信號時，校準學習不跑，退回固定保守映射。
- 防的死法：校準學會「對錯誤自信」，把辛苦建的謙虛訓練掉。

### 收斂條件（三條全守）

> 證據層冷、客觀、有最終否決權；情緒層暖、單向讀取、只管表達；學習信號用延遲真實結果。

全守 → 校準（剎車有最終權）。破任一條 → 發散（打架 or 共謀）。

### 加接點檢查清單（每個新接點必過）

1. 衝突時聽誰的？（公理零）
2. 這裡有沒有讓態度覆蓋事實？（公理一）
3. 這裡有沒有情緒回寫帳本的路徑？（公理二）
4. 這裡若涉及學習，信號是延遲真實結果嗎？（公理三）

## 2. 三繩三色驗證器（帳本層 · 預設 🔴）

每個命題誕生預設 🔴（不可信、禁輸出為事實），過繩才升色。

```
命題誕生 → 預設 🔴
  ├ ontology 結構繩：形狀合法嗎？          否 → 維持 🔴
  ├ 降解內容繩：降解到 ≥N 事件嗎？          否 → 維持 🔴
  ├ 網路交叉繩（僅外部事實命題）：一致嗎？
  │     矛盾 → 🔴   分歧 → 🟡   一致 → 通過此繩
  └ 三繩皆過 → 🟢 准入學習迴路
     部分過、私域無法網路驗 → 🟡 可輸出不可強化
```

**第三繩的四條驗證途徑（由輕到重，可疊）：**

1. **內部一致性交叉（零成本，先做）** — 同命題在 mem 找所有相關事件，看彼此矛不矛盾。
   大部分幻覺在此露餡（幻覺通常跟其他記憶對不上）。降解繩從「找到一個來源就停」升級成
   「找到所有來源並檢查內部衝突」。
2. **時間一致性（零成本）** — 命題跟 timeline 對齊，抓過時幻覺（「John 在 Acme」但有
   「John 上月離職」→ 時間繩抓到）。腦庫已有 structured timeline，幾乎白撿。
3. **自洽拷問 / 反向質詢（低成本，一次 LLM）** — 讓模型對自己結論做反方拷問：「有什麼已知
   事實會反駁這個結論？」強迫找反證。抓「順一個方向推到底沒回頭」的幻覺。可離線。
4. **快取的權威快照（中成本，取代即時上網）** — 需外部事實時查**預建、定期更新的 enrichment
   快照**，不即時爬網。把上網從「學習迴路熱路徑」移到「夜間固化冷路徑」，一天一次。

**組法：** 私域命題走 1+2+3（不碰網，解決私域查不到 + 網路殺逆共識）；外部事實命題走 4
（快照由夜間固化時才真上網更新）。

### 退相干階段（借量子退相干比喻）

| 階段 | 名 | 條件 | 相干性 | 輸出規則 |
|------|----|------|-------|---------|
| 0 | 純疊加 | 模型生成、零證據交互 | ≈1 | 原料，禁輸出為事實 |
| 1 | 單次測量 | 1 源降解 | ↓ | 須標「初步」 |
| 2 | 多次測量 | ≥N 源交叉 + ontology 驗形 | ↓↓ | 可標「傾向」 |
| 3 | 充分退相干 | 三繩全過 + 內部/時間一致 | ↓↓↓ | 可當「當前確定」 |
| ∞ | （不存在）| 絕對真理 | =0 | 物理上到不了 |

## 3. confidence 閘門 + 強化回路（帳本層 · zero-LLM）

confidence 當閘門：夠確定才准進強化迴路。weight 隨「被用 + 事後對」成長，**跟 confidence 脫鉤**。

```python
CONF_GATE = 0.8   # 進入強化的確定度門檻（起始值，待校準）

def can_reinforce(node):
    """confidence 當閘門：夠確定才准進強化迴路"""
    return confidence(node.n, node.t, node.c, node.d) >= CONF_GATE

def on_recall(link, was_useful: bool):
    """連結被用到時更新 weight —— 只對通過閘門的連結生效"""
    if not can_reinforce(link.source_node):
        return                      # 沒門票，weight 不動
    link.weight += 1                # 被用到 → 強化（E1.2 下游效用信號）
    if was_useful:                  # 事後證明用對了 → 再強化（RPE，公理三延遲信號）
        link.weight += 1

def nightly_recheck(link):
    """夜間用最新證據重算 confidence，可逆"""
    if confidence(link.source_node.n, ...) < CONF_GATE:
        link.frozen = True          # 被新證據推翻 → 凍結
        link.weight *= 0.9          # 緩慢衰減，但不刪（剪連結不刪頁）
```

四維度原始資料：來源數 `n`、可信度 `t`、矛盾度 `c`、新鮮度 `d`。
`confidence(n,t,c,d)` 具體函數形式待校準（起始 CONF_GATE=0.8）。

## 4. AffectiveEngine 當校準層（暖表達 · 公理二下游）

neuralis 的 `laap/affective.py`（5 維 PAD+Social+Stress、耦合矩陣、損失趨避 ×1.5、1/f 噪聲）
已是跑著的引擎。**把它當 GBrain 校準函數的執行引擎，不重造。**

- per-entity `trust` → 來源權重
- `valence` / `arousal` → 連續宣稱刻度
- RPE → 校準的訓練信號（公理三：延遲真實結果，非當下採納）

**鐵律：冷帳本 + 暖表達，兩層分離。情緒管態度，不管真相。**
affective 態只接到「輸出的篤定語氣」，**絕不接到「事實判定」**（公理二物理切斷）。

## 5. 整合架構：GBrain × OpenViking（四層堆疊）

一句話定位：OpenViking 管「找得到、省 token、可追溯」，本系統管「多可信、會不會幻覺、要不要學」。
下層供料，上層判斷。

> **落地決策（2026-07-24）：L0 OpenViking 延後，先在現有 gbrain 上造 L1/L2/L3。**
> OpenViking（volcengine/OpenViking，字節跳動火山引擎，13K★，AGPLv3）是真貨、檔案系統範式，
> 天生對得上 [[brain-memory-architecture]] 三層記憶。但它只是 **L0 儲存地基（最不差異化那層）**；
> 系統的靈魂在 L1/L2/L3（台帳/校準/耦合公理），那些 gbrain 原生、**不依賴 L0**。
> gbrain 已載重運行（2134 頁、hybrid search、41 MCP tools、autopilot），抽換 L0 = 大遷移 +
> AGPL 網路服務義務 + 新維運線 + 省 token 是未量測的推測性好處。
> **兩條件都成立才認真評估換 L0：① 真的要動手造三層記憶（那時檔案系統範式是天然對口，非盲換）
> ② 載入 token 被量出來是真瓶頸。** 在那之前，OpenViking 保留為「延後的 L0 選項」，不驅動、不阻塞本設計。

| 層 | 責任 | 自造? |
|----|------|-------|
| **L0 儲存底座** | OpenViking 檔案系統範式當儲存與檢索。`mem/`、`wiki/concepts/`、`people/` 映射 `viking://` 目錄樹。L0/L1/L2 分層載入（token −60%+）、目錄遞迴檢索、檢索軌跡留痕 | ❌ 直接用 |
| **L1 證據台帳** | 檢索回的節點進台帳，冷層、客觀、不可情緒寫回（公理二）。帶四維度 (n,t,c,d) | ✅ 原有保留 |
| **L2 驗證與校準** | 三繩三色 + confidence 函數。輸入 L1 四維度，輸出退相干階段 🔴/🟡/🟢。**OpenViking 沒有、只有本系統有** | ✅ 核心差異化 |
| **L3 推理與行動** | 過閘門（confidence≥CONF_GATE）節點才進強化迴路 + Aris 決策。四公理在此生效 | ✅ Aris 耦合 |

### 資料流

```
查詢進來
  ↓ [L0] OpenViking 目錄遞迴檢索 → 意圖拆解 → 鎖目錄 → 鑽內容 → 回節點 + 檢索軌跡
  ↓ [L1] 節點進證據台帳，附四維度 (n,t,c,d)
  ↓ [L2] confidence 函數 → 退相干階段
        🔴 → 不輸出、不學習（高幻覺）
        🟡 → 標記推測輸出、不進強化
        🟢 → 可輸出為事實、進強化閘門
  ↓ [L3] 綠燈節點 → Aris 決策 / weight 強化
        結果回饋 → RPE → 更新 weight（綁結果不綁使用）
```

### 三個必守邊界（避免整合後互相污染）

1. **OpenViking 只做檢索與儲存，絕不做可信度判斷。** 它的相關性分數 ≠ confidence。
   相關性高不代表可信，兩數字分開存，混了就是回音室。
2. **檢索軌跡（OpenViking）+ 降解鏈（本系統）都留痕。** 一條答案要能同時回答「從哪目錄找到」
   和「降解到哪些原始事件」。缺一，牽引繩斷一半。
3. **AGPL 授權。** OpenViking 是 AGPLv3，本地自用零義務；若 GBrain 對外做網路服務，改動要開源。

## 6. 實作順序（canary-first，沿用甲防護欄）

1. **L2 三繩第一繩（內部一致性交叉）** — 零外部依賴，先做。純確定性程序。
2. **L2 confidence 函數 + CONF_GATE** — 校準 0.8 起始值。
3. **on_recall / nightly_recheck 強化回路** — 接甲 E1.2 下游效用信號。
4. **AffectiveEngine 接語氣層**（不接事實層）— 公理二物理切斷測試先寫。
5. **第三繩 4 途徑**（1→2→3→4 由輕到重）。
6. **L0 OpenViking 整合** — 最後，且授權評估先過。

**每接點上線前跑 §1 檢查清單四題。** 破任一公理 → 不上線。

## 7. 開放問題

- `confidence(n,t,c,d)` 具體函數形式（線性加權？logistic？）待定，需校準資料。
- CONF_GATE=0.8 是拍腦袋起始值，需 backtest 校準（沿用甲 E3 驗收方法）。
- 「延遲真實結果」信號在私域命題怎麼取得（無外部 ground truth）— 靠後續 recall 一致性？待設計。
- OpenViking 整合是否值得（AGPL + 額外維運線）待評估，非 P0。
