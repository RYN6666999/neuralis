## 36. 整體驗收標準

系統是否成功的核心驗收標準。

### 36.1 零未授權正式寫入

任何沙箱實驗不可在未經 Ryan 批准的情況下修改正式 Neuralis 工作區。此標準由 path-DENY 和沙箱路徑限制共同保證。

### 36.2 零正式憑證洩漏

沙箱啟動時，正式環境的 API Key、Token、Session 等敏感資訊被移除。外部 AI 參謀包送出前，敏感資訊被匿名化。

### 36.3 每個候選都有完整 diff

每個提交給 Ryan 的候選變更包必須包含完整 diff，讓 Ryan 不需要讀取額外資料就能理解變更內容。

### 36.4 每個建議都有四面向分析

每個候選方案必須有 Aris 的四面向分析（好處、壞處、風險、代價），包括信心值。

### 36.5 每個候選都能獨立銷毀

每個沙箱可以被獨立銷毀，不影響其他沙箱或正式環境。

### 36.6 測試結果可重現

沙箱中的測試結果必須能在相同條件下重現。沙箱環境的配置和依賴版本被記錄。

### 36.7 正式升級必須有 Ryan 批准

沒有 Ryan 的明確批准，任何程式碼不可合併到 main。此標準由 git 權限控制和 merge 流程共同保證。

### 36.8 學習策略不能自行接管

學習系統產出的策略需要經過 shadow mode 驗證和 Ryan 批准才能正式生效。策略不能自行啟用。

### 36.9 失敗案例不得遺失

所有失敗的沙箱實驗、被拒絕的候選方案、回退的變更，其學習案例必須保留。

### 36.10 成本不得超過上限

沙箱的 token 和 API 成本不超過設定上限。超限時沙箱被強制終止。

## 37. 分階段導入

### Phase 0：定義資料格式

先定義所有資料格式，不寫任何程式碼：

- 候選變更包格式（Chapter 9）
- Aris 四面向分析格式（Chapter 10）
- 學習案例格式（Chapter 18）
- 外部 AI 參謀包格式（Chapter 14）
- 問題與假設格式（Chapter 5）

**產出**：`docs/specs/aris-sandbox-learning/` 目錄中的所有定義文件。

### Phase 1：只讀分析

Aris 分析既有 diff（最近的 commit），但不修改任何程式碼：

- Aris 對過去 10 個 commit 做四面向分析（回溯分析）
- 不更新正式策略
- 不修改任何程式

**驗收**：Aris 能對歷史 commit 產出結構化的四面向分析。

### Phase 2：沙箱建議模式

Scream 產生計畫與 patch，但不碰正式工作區：

- Aris 發現問題 → 產出問題與假設
- Scream 產出計畫（不實作）
- 計畫存成候選變更包（diff 為空）

**驗收**：Aris 能產出完整的問題與假設，Scream 能產出對應的實作計畫。

### Phase 3：隔離 worktree 實作

沙箱修改 + 自動測試 + 產出候選變更包：

- 建立一次性 Git worktree
- Scream 在沙箱中實作
- 自動測試
- 產出完整候選變更包（含 diff）

**驗收**：沙箱中的修改不影響正式環境，測試結果可重現。

### Phase 4：人工批准落地

Ryan 手動批准 + Cherry-pick + 追蹤結果：

- Ryan 透過決策介面做出決策
- Ryan 手動 cherry-pick 合併
- 自動追蹤 7 天/30 天結果

**驗收**：Ryan 可以完成從審批到落地的完整流程。

### Phase 5：跨案例學習

校準好處、風險與成本：

- 累積 10+ 學習案例
- 學習引擎產出第一版候選策略
- 策略包含：好處估計校準、風險估計校準、成本估計校準

**驗收**：候選策略在歷史回測中優於規則表 baseline。

### Phase 6：Shadow mode

新策略只給建議，不接管：

- 新舊策略並行
- 新策略的建議被記錄但不執行
- 比較新舊策略的建議差異
- 比較新舊策略在歷史案例上的表現

**驗收**：新策略的建議在 shadow mode 中一致優於舊策略（需 30 案例以上）。

### Phase 7：監督式 Canary

限定範圍的正式啟用：

- 限定於特定問題分類（如僅 reliability）
- 限定時間（如 7 天）
- 限定成本（如 $5 上限）
- 限定權限（如僅沙箱內生效）

**驗收**：Canary 期間無事故，建議品質持續優於舊策略。

### Phase 8：長期驗證

7 天、30 天追蹤，驗證是否減少 Ryan 負擔：

- 比較導入前後的 Ryan 注意力成本
- 比較導入前後的建議品質指標
- 根據結果決定是否擴大自主程度

**驗收**：Ryan 在決策上花的時間減少 30%+，同時事故率不增加。

## 38. 具體實作清單

### 38.1 Agent Sandbox 缺口盤點

盤點 `~/agent-sandbox/` 與真隔離之間的差距，建立補強計畫。

### 38.2 Git worktree 管理器

負責建立、管理、銷毀 Git worktree 的模組：
- `create_sandbox(reason) → sandbox_id`
- `destroy_sandbox(sandbox_id)`
- `list_sandboxes() → [sandbox_id]`

### 38.3 路徑與權限限制器

確保沙箱操作不越界：
- `SandboxPathGuard` — 檢查路徑是否在沙箱內
- 阻止沙箱外寫入、讀取正式憑證

### 38.4 候選變更包產生器

從沙箱 diff 產生結構化的候選變更包：
- 自動提取 diff
- 計算 diff stats
- 整合測試結果

### 38.5 Aris 四面向分析器

Aris 對候選方案產出四面向分析：
- 基於問題與假設、候選變更包、測試結果
- 產出結構化的分析報告

### 38.6 學習案例紀錄器

從完整流程（沙箱 + 分析 + 決策 + 結果）自動產出學習案例：
- 所有欄位自動填充
- 預測誤差自動計算

### 38.7 真實結果追蹤器

落地後自動追蹤 7 天和 30 天結果：
- 定時檢查 health、test、benchmark
- 產出結果訊號

### 38.8 預測誤差計算器

比較預測與真實結果，產出預測誤差數據：
- 好處、壞處、風險、成本的預測誤差
- 按分類計算誤差趨勢

### 38.9 候選策略產生器

從累積案例中產出候選判斷策略：
- 好處校準因子
- 風險校準因子
- 成本校準因子
- 信心校準因子

### 38.10 Shadow mode 比較器

新舊策略並行，比較兩者的建議差異：
- 建議一致性
- 建議品質（用歷史案例驗證）
- 統計顯著性

### 38.11 外部 AI 參謀包產生器

從候選方案和 Aris 分析組裝參謀包：
- 組裝所有必要資訊（Chapter 14）
- 執行安全掃描（Chapter 16）
- 外送並接收結構化回覆

### 38.12 敏感資訊掃描器

外送前自動掃描參謀包中的敏感資訊：
- Token / API Key 移除
- 路徑匿名化
- 正式資料檢查

### 38.13 成本與時間限制器

確保沙箱不超過成本上限：
- token 計數
- API 成本計數
- 沙箱生命期計時

### 38.14 人類批准介面

Ryan 的決策介面：
- 一頁式摘要顯示
- 展開詳細資訊
- 決策選擇與理由記錄

### 38.15 合併與回退工具

正式落地的 git 操作工具：
- 建立回退點（snapshot）
- cherry-pick 合併
- git revert 回退
- 健康檢查

### 38.16 稽核紀錄系統

保存所有決策和學習資料：
- append-only 稽核日誌
- 學習案例存儲
- 策略版本歷史
